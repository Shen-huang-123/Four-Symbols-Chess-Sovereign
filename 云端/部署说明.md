# 四象棋尊 JSON 云存档部署说明

当前交付的是可部署的 AWS SAM / Lambda 后端和 Android 客户端接口。**尚未创建私有存档仓库、部署云函数或进行真实云端验收**。不需要 SQL 数据库，不需要常驻服务器。游戏离线运行不依赖此服务。

## 1. 准备与隔离

1. 新建一个专用 **Private** GitHub 仓库，例如 `你的账号/four-chess-private-archive`。不要使用公开游戏源码仓库保存玩家档案。
2. 初始化 `main` 分支，并把本目录的 `schema-version.json` 放到仓库根目录。该文件用于记录格式；接口仍逐份校验 `schema=1`。
3. 创建 fine-grained GitHub Token，只选择这个存档仓库，授予 **Contents: Read and write**；设置有效期。Token 只配置到服务端，不能放进 APK、游戏源码、GitHub Release 或聊天。
4. 准备 AWS 账号、已认证的 AWS CLI、AWS SAM CLI、Docker。选择支持 Lambda Python 3.12 x86_64 的区域。可用额度、API 请求和 GitHub 配额需按账户自行检查，不承诺永久免费。

后端每次冷启动检查仓库的 `private` 属性，公开仓库会拒绝服务。

## 2. 服务端配置

| SAM 参数 | Lambda 环境变量 | 内容 |
|---|---|---|
| ArchiveRepository | ARCHIVE_REPOSITORY | `owner/private-repository` |
| ArchiveBranch | ARCHIVE_BRANCH | 已存在的分支，默认 `main` |
| ArchiveToken | GITHUB_ARCHIVE_TOKEN | 上述服务端专用 Token |
| SessionKey | SESSION_SIGNING_KEY | 至少 32 字节的随机签名密钥 |

`.env.example` 只列出变量名。程序不会自动加载 `.env`，以 Lambda 实际环境变量为准。两项密钥参数标为 NoEcho。不要将真实参数文件或 `samconfig.toml` 提交到 Git。生产运维可以改为 Secrets Manager 引用，再按需授予读取权限。

可在你自己的终端用 Python `secrets.token_urlsafe(48)` 生成签名密钥。不要使用示例字符串。更换签名密钥会使已有会话全部失效，不影响密码和档案。

## 3. 构建与部署

在本目录执行：

```powershell
sam validate --lint
sam build --use-container
sam deploy --guided --capabilities CAPABILITY_IAM
```

容器构建用于把 argon2-cffi 依赖打包为 Linux x86_64 版本；不要直接把 Windows 的 pip 安装目录上传 Lambda。按引导填写参数，创建独立 stack，**不要保存包含密钥的部署参数到仓库**。若账户 Lambda 并发额度不足，先申请额度，再调整 `ReservedConcurrentExecutions`，不能把部署失败视为成功。

部署完成取得 Outputs 中的 `Endpoint`（HTTPS 根地址，不含 `/v1`）。在游戏主页点击 **档案 → 账号与云存档 → 设置云端HTTPS地址**，填入该地址，再注册或登录。首次注册产生新的服务器 UUID 和默认档案；本机已有的独立档案不会被自动合并成新账号，避免身份归属混淆。

模板包含 API Gateway 基础限流（2请求/秒，突发10）和 Lambda 并发2。应用另有跨冷启动共享的15分钟计数器：同IP注册/登录80次、单账号15次、认证档案请求120次。真实用户量增加前应评估 GitHub Contents API 的读写配额与成本；此方案适合低并发存档，不用于高频实时游戏同步。

## 4. 实际存储结构

```text
schema-version.json
accounts/<账号小写后的SHA256>.json
players/<服务端生成的UUID>/document.json
limits/<HMAC后的限流桶>.json
```

账号文件只保存 UUID、Argon2id 密码哈希、会话版本和创建时间。每位玩家使用独立 `document.json`，包含 `revision` 和完整 `document`。个人资料、统计、成就、好友、角色、衣橱、棋局集中在同一次 JSON 提交中，避免拆为多个文件后只成功写入一半。没有全体玩家下载接口。

单份档案上限 750,000 字节，棋局最多5000、好友最多500、撤销标记最多5000；超过容量会明确失败并保留本地，不自动删除历史。应在接近上限时导出备份并规划下一版存档分片迁移，不能直接截断 JSON。GitHub 提交历史也包含历史私密资料，应限制仓库协作者和 Token 权限。

## 5. API 合约

请求/响应均为 JSON，账号接口不记录密码和令牌。认证接口使用 `Authorization: Bearer <session>`。客户端不能通过传入别人的 UUID 访问另一份档案。

| 方法与路径 | 请求 | 返回 |
|---|---|---|
| POST /v1/register | account, password | session, revision, document |
| POST /v1/login | account, password | session, revision, document |
| GET /v1/profile | 无 | 本人 revision, document |
| PUT /v1/profile | revision, document | 新 revision, document |
| POST /v1/password | oldPassword, newPassword | 新 session |
| POST /v1/logout | 空对象 | ok |

账号4～32位字母、数字或下划线，大小写不区分；密码10～128字符。Argon2id 参数：内存65536KiB、迭代3、并行1，随机盐16字节。会话 HMAC-SHA256 签名，期限14天；改密码或服务端成功退出会提升账号会话版本，**使该账号所有设备的旧会话失效**。

常见状态码：400格式错误、401会话或密码错误、409重复账号或修订冲突、413容量超限、429限流、503暂不可用。409存档冲突返回当前 `revision/document`；客户端显式选择资料来源后，按棋局 UUID 合并，撤销记录使用 tombstone 防止旧设备恢复已悔棋记录。相同棋局 ID 内容不一致时拒绝静默合并。

客户端在请求期间发生新编辑，也会合并响应与新编辑，不会仅更新修订号后把另一台设备的新棋局覆盖掉。云端通过修订号和 GitHub 文件 SHA 双重检查，防止读取后发生竞争写入。

## 6. 本地验证（无需任何凭据）

使用隔离的 Python 环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m unittest discover -s . -v
```

测试使用真实 Argon2id 与支持 CAS 的内存仓库适配器，检查注册、正确/错误密码、会话、撤销、越权、卸载缓存后恢复合约、修订竞争和限流。它验证接口逻辑，**不等于 AWS/GitHub 已部署验证，也不等于真实手机已完成卸载重装恢复**。

## 7. 部署后验收清单

- 用两个新账号注册；正确密码登录，错误密码返回401。
- 修改资料并同步，确认私有仓库只出现对应 UUID 档案和 Argon2id 哈希。
- 使用甲会话尝试上传乙UUID，确认400；按乙UUID拼接读取路径确认404。
- 两设备读取同修订，先后写入，第二次必须409；在游戏中显式合并后重试。
- 修改密码后旧会话失效，旧密码不能登录。
- 成功同步后，在测试设备清除数据/重装，用同账号恢复已同步的资料。
- 断网修改资料、完成对局，确认仍可读取本地；恢复网络并保持应用运行，确认重试成功。
- 检查日志未启用请求体、Authorization头或带凭据的追踪；观察429、503和GitHub配额。

## 8. 产品边界

- 本机正式档案可离线养成；游客不计正式战绩。只有登录并同步成功的云端账号才可重装恢复。
- Android 使用 Keystore AES-GCM 保存会话，不保存密码；换接口地址会清掉旧会话。应用开启时按15秒起步、失败退避至最多5分钟重试脏档案。应用被系统杀死时不承诺后台同步，重新打开后继续。
- 好友是本机/局域网交换的公开名片；身份自报，亲密度归各自档案所有。不能修改另一位玩家私有 JSON，不伪造在线状态，也未实现云端双向好友申请服务。
- 局域网对局由现有房主裁决，战绩来自客户端记录。这不是防作弊排位服务器；云端授权保护档案访问，不证明本地胜场真实性。
- 当前规则没有平局或完整淘汰排名：只记录真实胜负与胜者第1名，其他名次不编造；结盟不等于团队胜利，因此不发放虚构的同队胜利亲密度。
- GitHub存档不是端到端加密：运营者/获授权的私有仓库协作者可以读取资料，需按自己的隐私与保留政策管理。

实现依据：[GitHub Contents API](https://docs.github.com/en/rest/repos/contents?apiVersion=2022-11-28)、[argon2-cffi API](https://argon2-cffi.readthedocs.io/en/stable/api.html)、[AWS SAM Function](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/sam-resource-function.html)。
