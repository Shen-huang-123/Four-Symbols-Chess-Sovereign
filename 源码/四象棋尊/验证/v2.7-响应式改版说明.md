# 四象棋尊 v2.7 手机响应式改版

本次直接修改原生 Android Java / ViewGroup / Canvas 工程，继续使用已有角色素材、真实棋盘和事件绑定。没有引入网页、CSS 或静态棋盘图片。交付版本 2.7.0，versionCode 27。

## 原因与布局规则

v2.6 使用单一横屏布局，右栏最小宽度 152 dp，棋谱长期驻留，棋盘横纵网格分别拉伸。手机显示密度较高时，物理分辨率虽大，可用 dp 仍有限。本轮按扣除系统栏、挖孔与手势安全区域后的真实窗口尺寸测量，不再按设备像素数判定桌面布局。

断点按以下顺序判断：

| 模式 | 条件 | 玩家栏 | 棋盘与操作 |
| --- | --- | --- | --- |
| 宽窗口 | 宽至少 840 dp 且高至少 600 dp | 54 dp，四卡一行 | 等比例棋盘，保留完整右侧状态、棋谱及按钮 |
| 手机横屏 | 不满足宽窗口且宽大于高 | 34 dp；高度不足 300 dp 时 28 dp | 隐藏外围装饰、说明与常驻棋谱，紧凑操作栏 |
| 竖屏 | 其余窗口 | 84 dp，四卡两行 | 等比例棋盘，底部操作区与横屏提示；模式选择页单独适配竖屏 |

- 手机间隔 4 dp，宽窗口 8 dp；玩家栏最高不超过窗口高度的 1/5。
- 横屏操作栏常规 68 dp，系统字体超过 120% 时 80 dp。低高度窗口使用 124 dp、两列按钮；另受窗口宽度比例约束。
- 竖屏底部操作区约 84～104 dp。所有子区域先测量，再布局，不覆盖棋盘。
- 手机棋谱通过“棋谱”按钮打开独立滚动弹窗，可切换标准/大字棋子；局域网详细状态及地址也在弹窗顶部显示。模式、规则、悔棋和声音复用原有事件。
- Android 支持横竖屏切换；配置变更重新测量布局，不销毁当前棋盘或清空棋局。已打开的棋谱弹窗随窗口变化调整尺寸。
- 宽窗口继续复用已有 MatchPanelLayout。项目没有单独的 Windows 或 Web 桌面客户端，宽窗口验收指 Android 大窗口。

## 实际棋盘计算

四方十字结构仍为原始 19×19 逻辑坐标、261 个有效交叉点、64 枚初始棋子。没有删减交叉点或改动规则。

先从安全窗口扣除玩家栏、操作区及间隔，得到可用宽高；棋盘 View 边长取二者较小值。设棋盘 View 实测宽高为 W、H（像素），density 为系统密度：

```text
padding = 2 × density
cell = max(1, 0.95 × min(W - 2×padding, H - 2×padding) / 18.96)
cellX = cellY = cell
ox = (W - 18×cell) / 2
oy = (H - 18×cell) / 2
棋子中心 = (ox + x×cell, oy + y×cell)
默认棋子直径 = cell × 0.70
可选大字直径 = cell × 0.84
```

18.96 是包含外沿余量的框架跨度。95% 以当前可用框架的最大等比例适配尺寸为基准，而非固定物理像素。宽高方向使用相同间距，不再拉伸网格。触摸仍使用相同 ox/oy/cell 的原有逆变换，逻辑坐标不变。

默认文字目标字号为 cell×0.552，大字档为 cell×0.65，使用加粗中文字体回退；根据真实字形边界把最大笔画范围限制在棋子直径的 71% 内，并按字形居中。浅象牙棋面、细边框与轻微阴影保留。

首次进入 v2.7 恢复标准 70% 档，之后保存用户的 70%/84% 偏好。长按 450 ms 打开 2.4 倍局部放大，松手不会落子；160 ms 走棋动画不延迟真实状态更新。

等比例完整棋盘受屏幕短边约束，超宽手机两侧仍有自然余量。不能同时保证全部交叉点完整显示、正方形网格和铺满所有长边空间。极低高度窗口的棋子物理像素仍有限，可使用大字档与局部放大；没有以裁切或改变规则换取表面上的大棋子。
