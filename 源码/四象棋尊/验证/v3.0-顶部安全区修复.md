# v3.0 顶部安全区背景缺块修复

## 原因与修复

截图顶部的纯深色横条来自根 FrameLayout 的安全区 padding。原先安全区以纯色填充，庭院背景仅在模式页 / 对局页子视图内绘制，导致刘海区域与页面之间出现整条分界。底部手势区同样存在这一问题。

现在新增 GameWindowLayout 作为全窗口背景层，庭院及模式页暗色罩从窗口 0,0 绘制到底边。两个页面背景透明，内容继续使用 MainActivity 原有 applySafeInsets 计算，保留刘海、系统栏与底部手势避让。没有将标题或返回按钮推到摄像头下面。游戏布局尺寸、棋盘坐标及业务功能未修改。

ModeSelectView 在实际可用高度小于 220 dp 的极矮横屏下压缩装饰：4 dp 外边距、24 dp 标题区、3 dp 卡片间距，取消副标题与页脚，卡片仍保留最少 44 dp 触摸高度。避免扣除顶部安全区后第三张模式卡超出屏幕。

- app/src/main/java/com/dorm/fourchess/MainActivity.java：改用背景根容器，游戏页透明，切换页面时刷新背景。
- app/src/main/java/com/dorm/fourchess/DuelLayout.java：去除局部庭院底图，复用全窗口场景。
- app/src/main/java/com/dorm/fourchess/ModeSelectView.java：去除局部背景和遮罩，极矮横屏避让修正。
- app/build.gradle：3.0.0 / versionCode 30，build-v30 构建输出及安全区域测试运行器。
- app/src/androidTest/java/com/dorm/fourchess/SafeAreaProbe.java：新增真实窗口与注入安全区回归。
- 验证/VerifySafeArea.ps1：配置与截图导出；v3.0-safe-*.txt、v3.0-*.png 保存日志和截图。
- D 盘根 README、本文、保护源码哈希及安装包校验值。

CourtyardScene、美术资源、棋盘渲染、棋子坐标、规则、网络和声音代码没有改动。v3.0-protected-sources.json 中 10 个未修改生产文件全部通过 SHA256 对照。

## 验证结果

Android 15 原生模拟器：4 组共 360 项断言通过。

| 配置 | 窗口像素 | 最终实际安全区 左/上/右/下 px | 检查 |
|---|---|---|---|
| 竖屏 | 1272×2800 | 0/0/0/18 | 88 PASS |
| 启用系统刘海模拟的竖屏 | 1272×2800 | 0/0/0/18 | 88 PASS |
| 系统刘海横屏 | 2800×1272 | 126/0/0/18 | 92 PASS |
| 低高度刘海横屏 | 1280×720 | 58/0/0/18 | 92 PASS |

每组额外显式注入顶部 150 px、左侧 110 px、右侧 110 px 与底部 24 px 安全区；模式页和对局页均逐像素抽样检查安全边距由不透明场景填充、不再为旧纯色，控件仍位于安全区域。测试根窗口从屏幕原点开始、模式卡完整、开局、合法走棋、回合推进、悔棋状态恢复、返回保留棋局及横竖屏切换。

系统刘海模拟在本模拟器竖屏未报告顶部 inset，因此顶部缺块的直接复现使用显式注入的 150 px inset；保留了该配置下模式页和对局页的真实窗口截图（*-cutout-mode.png、*-cutout-game.png），不是只检查没有安全区的画面。已人工查看顶部注入截图及极矮横屏截图。

离线构建 assembleDebug / assembleDebugAndroidTest 成功。APK 使用原签名，包名 com.dorm.fourchess；可覆盖安装。没有荣耀 WIN 真机远程连接，需真机最终确认厂商全屏设置效果。
