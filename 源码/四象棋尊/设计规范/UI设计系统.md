# 四象棋尊 UI 设计系统 · 1.0

实施版本：v4.1。定位：月夜庭院中的四方策略对弈。规范由 `GameDesign.java` 提供，组件读取语义 token，不能在新页面重复建立另一套金色、字体或按钮系统。

## 组件与素材盘点

| 组件 | 责任 | 本轮接入 |
| --- | --- | --- |
| ModeSelectView | 主视觉、玩法切换、三种入局入口 | 文字层级、卡片材质、统一边框与反馈 |
| FactionStripView | 四角色头像、昵称、阵营、计时 | 阵营色、统一文字、行动边框、短过渡 |
| ActionDockButton / ActionGlyph | 原生可访问操作按钮与代码图标 | 统一材质、图标语言和按压反馈 |
| BattleSkin.Frame | 宽屏面板与按钮容器 | 单层细边与半透明蓝灰，移除双层厚边和纹理横线 |
| GameDialogStyle | 昵称、规则、模式、棋谱等原生弹窗 | 标题、文字、输入状态、动作与间距 |
| DuelLayout / CompactControlsLayout | 三类尺寸布局与操作托盘 | 保留独立布局，统一颜色与材质 |
| FourChessView / BoardFeedback | 真实棋盘、棋子与落点反馈 | 仅接入棋面、网格、阵营字色与字体 token；坐标算法不变 |
| CourtyardScene / GameWindowLayout | 独立分层场景和遮罩 | 墨青夜色；棋盘不包含在场景素材内 |

现有位图：`drawable-nodpi/ui_reference.png`（四个角色合图，本轮沿用原头像裁切位置）；`app_icon_art.png`（应用图标）。`drawable/app_icon.xml` 是图标入口。庭院、远山、月光、灯笼、樱花使用现有代码绘制。没有新增位图、占位人物或外部字体。

## 字体、尺寸与材质

- 标题：系统 serif bold，仅品牌；功能标题/角色名：sans-serif-medium；正文：sans-serif；棋字：sans-serif bold。Typeface 全局缓存，中文使用 Android 系统回退。
- 标准字号：品牌 29sp、功能标题 19sp、正文 15sp、标签 12sp、辅助 11sp。手机 HUD 依据实际卡片高度计算，长昵称省略；模式卡根据可用宽高收敛字号。保留现有系统字体放大适配。
- 间距：4 / 8 / 12 / 16 / 24dp。不要建立零散装饰间距。
- 圆角：输入/小控件 8dp，面板 12dp，弹窗 16dp；极矮控件半径受其高度约束。操作 Dock 保留圆形图标。
- 描边：常态 0.7dp，行动/焦点约 1.1dp；Canvas 按实际 density 绘制。原生输入边框使用完整物理像素。
- 阴影：#40071019，位移 2–3dp；不使用强外发光或厚重斜面。面板允许轻微上下明暗，禁止大面积高饱和渐变。
- 原生可操作入口目标至少 44dp，保留键盘、TalkBack 和禁用状态。极低高度依靠双列操作区；不以扩大视觉图标代替真实触摸区域。

## 层级与页面

模式页重点为三个可交互入局卡片，品牌和角色用于建立氛围。角色标题降至 19sp，卡片保持清晰暖白文字，玩法切换使用较安静的深色容器。不要把角色、标题和按钮同时强发光。

对局页重点是浅色真实棋盘；HUD 的当前行动边框和计时为次级信息。宽屏状态、历史、操作三个区域保留；手机详细棋谱和设置继续通过弹窗打开，避免长期占用棋盘。

## 响应式约束（沿用已验证结构）

- 依据实际内容区域计算，系统安全区由现有窗口 inset 逻辑扣除。
- 手机竖屏：两列两行 HUD，方形棋盘，下方状态条和操作 Dock；额外空间才显示品牌和底部短句。
- 手机横屏：一行紧凑 HUD，正方形棋盘 + 窄操作区；低于 300dp 高度时操作区两列。
- 宽屏：可用宽 ≥840dp 且高 ≥600dp，启用完整右侧面板；不靠整页 transform 缩放。
- 模式页分别计算竖屏主视觉/下方卡片与横屏左右分区，矮屏优先保留三个入口。
- 棋盘 cell = max(1, min(width-4dp,height-4dp) / 18.96 × 0.95)，cellX = cellY；ox = (width-18cell)/2，oy 同理。
- 标准棋子直径 0.70cell，大字选项 0.84cell；字体基准分别 0.552cell / 0.65cell，再以字形边界收敛。点击继续用同一 ox/oy/cell 逆变换。行列、交叉点、初始布局完全保留。

## 动效与状态

- 按下 80ms、释放 150ms；模式确认 220ms（沿用原入口防重复触发流程），卡片进入 300ms，回合边框 600ms。
- 棋子原有移动 160ms、落点反馈、技能目标、非法点击反馈保留，不能等待动画后才更新棋局。
- 默认、按压、选中/焦点、禁用可区分：填色轻微变化、金边、降权；不以持续闪烁表示选中。
- 环境花瓣保持稀疏，绘制排除棋盘、HUD 和控件区。遵从系统关闭动画，隐藏/失焦后停止申请新帧。禁止为每个按钮增加持续循环光效。

## 后续美术需求

本轮无需补充素材即可使用。要达到精绘角色立绘与场景质量，下一阶段需：

1. 四角色独立透明 PNG/WebP 半身立绘，各约 1200×1600，四种主题统一光源，发丝/袖口保持真透明；不能从头像强行拉伸。
2. 无文字、无按钮的夜樱庭院独立场景，竖屏 1440×3200、横屏 3200×1440；中心和 UI 区保持低对比。
3. 如需专用中文字体，需有可打包授权并包含全部棋字的字体文件。当前系统字体可正常使用。

后续分阶段替换资源；保留本规范、真实 UI、响应式约束及所有事件绑定。当前版本建立统一实现基础，不将缺少独立立绘的界面宣称为最终商业美术交付。
